# Building the Android APK

The mobile app is a **Capacitor shell around the live site**, not a bundled copy of it:
`capacitor.config.ts` sets `server.url` from `CAPACITOR_LIVE_URL`, so the WebView loads
`https://seltech.store` at runtime and `webDir` (`public/mobile-shell`) is only the placeholder shown
when that URL is missing.

Two consequences worth knowing before you build:

1. **The APK does not contain the web app.** Shipping a new APK is not how you ship a UI change —
   deploying the site is. You only need a new APK when the native side changes: a Capacitor plugin,
   an SDK version, the app id/name, the start URL, or permissions.
2. **`next build` is not part of the APK build.** That is why CI can build one without any of the
   web app's build-time secrets.

## The easy way: GitHub Actions

`.github/workflows/android-release.yml` builds a signed release APK and uploads it as a workflow
artifact. No local Android toolchain required.

**One-time setup.** Create a keystore (keep it somewhere safe and backed up — losing it means you can
never update an app already installed from it):

```bash
keytool -genkeypair -v \
  -keystore sel-release.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias sel
```

Base64 it so it can live in a secret:

```bash
base64 -w 0 sel-release.jks > sel-release.jks.b64    # Linux/Git Bash
# macOS: base64 -i sel-release.jks -o sel-release.jks.b64
```

Add four **repository secrets** under Settings → Secrets and variables → Actions:

| Secret | Value |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | the contents of `sel-release.jks.b64` |
| `ANDROID_KEYSTORE_PASSWORD` | the keystore password |
| `ANDROID_KEY_ALIAS` | the alias (`sel` above) |
| `ANDROID_KEY_PASSWORD` | the key password |

Optionally add a repository **variable** `CAPACITOR_LIVE_URL` if the site ever moves; it defaults to
`https://seltech.store`.

**Running it.** Actions tab → *Android release APK* → *Run workflow*. Choose `full` or `driver`, and
optionally a `versionName`. Pushing a `v*` tag also triggers it. The APK lands under the run's
Artifacts as `sel-<target>-release-<run>`.

The workflow fails fast and loudly in the two ways that matter: before building if any signing secret
is missing, and after building if the APK came out unsigned.

## Building locally

You need a JDK (21) and the Android SDK — installing Android Studio gets you both, since it bundles
its own JBR. Then:

```bash
npm run mobile:target:full:sync:android      # or :driver:
cd android
./gradlew assembleDebug                      # → app/build/outputs/apk/debug/app-debug.apk
```

`android/local.properties` must point at *your* SDK (`sdk.dir=…`). It is gitignored, so it holds
whatever the last machine wrote; if the path is wrong, Gradle stops with "SDK location not found".

For a signed release locally, point Gradle at your keystore with either environment variables or
`-P` properties:

```bash
ANDROID_KEYSTORE_PATH=/path/to/sel-release.jks \
ANDROID_KEYSTORE_PASSWORD=… ANDROID_KEY_ALIAS=sel ANDROID_KEY_PASSWORD=… \
  ./gradlew assembleRelease
```

Without them the release build still succeeds but the APK is **unsigned** and will not install —
`app/build.gradle` logs a line saying so at configuration time.

## The two app targets

`scripts/mobile-target.mjs` sets the env that `capacitor.config.ts` reads:

| Target | appId | Opens at |
| --- | --- | --- |
| `full` | `com.sel.full` (overridden to `com.sel` by `.env`) | `/` |
| `driver` | `com.sel.driver` | `/driver-management/mobile-hub` |

`.env` currently pins `CAPACITOR_APP_ID=com.sel` and `CAPACITOR_APP_NAME=SEL`, which is why the
locally generated config shows those rather than the per-target defaults. `applicationId` in
`android/app/build.gradle` is `com.sel` to match — changing the target's id means changing both.

## When the app shows a network error

`ERR_NAME_NOT_RESOLVED` and friends come from the WebView failing to reach `server.url`, before any
application code runs. Check, in order:

1. Open the same URL in Chrome **on the phone**. If that fails too it is device/network DNS (Private
   DNS, a VPN, or a resolver caching a stale record), not the app.
2. `adb logcat | grep -i chromium`, or `chrome://inspect` on a desktop with the phone plugged in, to
   see the actual failing request.
3. Confirm the baked URL: `android/app/src/main/assets/capacitor.config.json` (regenerated by
   `cap sync`, gitignored). If `server.url` is absent, `CAPACITOR_LIVE_URL` was unset at sync time and
   the app will show the `public/mobile-shell` placeholder instead.
